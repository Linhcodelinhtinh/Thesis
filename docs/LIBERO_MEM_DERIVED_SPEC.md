# LIBERO-Mem-derived T1/T3 — data and evaluation specification

**Classification:** `CUSTOM_V2_LIBERO_MEM_DERIVED` / `NON-COMPARABLE_OFFICIAL_PAPER`  
**Version:** derived replay data `libero_mem_derived_data_v1`; evaluator `libero_mem_t1_t3_v1`
**Parent study:** Chung et al., [arXiv:2511.11478v1](https://arxiv.org/abs/2511.11478)

## Scope and claims

This suite currently covers only the author-defined LIBERO-Mem tasks T1 and T3. It is a local controlled environment for paired model comparisons. It is not a reproduction of the paper's full ten-task result, and its scores must not be presented as official LIBERO or LIBERO-Mem scores.

The published source and local runtime do not establish that released demonstration images were generated by exactly the currently pinned author requirements. A local replay restored T1 `demo_33` exactly, then produced a different bottle pose after the 20-step warmup from the released refined image. This documents a source/artifact mismatch; it does not identify the cause. See [author runtime audit](LIBERO_MEM_AUTHOR_RUNTIME.md).

Nondeterministic physics can still support an informative comparison. Report the pinned runtime and fixed reset states, repeat rollouts, and use paired per-state comparisons with uncertainty. Policy seeds and repeated runs on one state are not new independent scene states. T1 and T3 share the same initial-state vectors, so their state-level observations are correlated.

## Environment and task contract

Policy inference runs on the Windows policy environment; simulation runs in the isolated WSL reference environment. The current simulator lock is Python 3.8.x, robosuite 1.4.0, MuJoCo 3.2.3, NumPy 1.22.4, BDDL 1.0.1 and robomimic 0.2.0. Robot/controller/cameras are Panda with the default gripper, `OSC_POSE`, 20 Hz, two 256×256 cameras (`agentview`, `robot0_eye_in_hand`) and native action shape 7. Exact controller parameters, source hashes and reset behavior are recorded in [the evaluator protocol](../configs/benchmarks/libero_mem_t1_t3_protocol.json).

| Task | Pinned BDDL task | Ordered milestones |
|---|---|---:|
| T1 | `KITCHEN_SCENE1_1_pick_up_the_bowl_and_place_it_back_on_the_plate` | 1 return of bowl 1 to plate 1 |
| T3 | `KITCHEN_SCENE1_3_lift_the_bowl_and_place_it_back_on_the_plate_3_times` | 3 returns of the same bowl to its plate |

This is not a bowl swap task. The protocol has a 1,000-policy-action horizon, policy action chunk size 50 and execution horizon 10. It warms up for 20 no-op actions `[0,0,0,0,0,0,-1]`; the Panda gripper convention is `-1` open and `+1` closed. At each policy-visible observation, the adapter increments the upstream evaluator once. The evaluator's live/nonlive counters are cumulative between milestones, not a consecutive-frame dwell rule. Success requires all milestones, the final predicate to hold and no upstream overshoot at the end of the episode.

## Split and derived demonstration contract

The parent assignment is `experiments/training/results_mem_2/mem-adapter-v1/dataset-split.lock.json`. Derived training data receives a new immutable lock from `scripts/lock_libero_mem_derived_split.py`; it inherits the parent's initial-state assignment, records the parent and derived-manifest hashes, and excludes unsuccessful or incomplete replay demonstrations from training. The parent lock remains the source for policy evaluation on its full held-out state roster.

Derived demonstrations replay the author's pinned actions after the same locked reset and warmup. A replay that reaches upstream terminal before its last source action is recorded as incomplete and is never written as a full trajectory. A completed replay is eligible for the training lock only when all task milestones are met, the final predicate is true, and no overshoot occurred. Missing source actions, wrong source hashes, absent task metadata, unknown measured state fields and incompatible staging configuration fail loudly.

The HDF5 contains observations before each executed source action, raw actions and measured state. It stores `robot_states=[gripper_qpos(2), eef_pos(3), quaternion_xyzw(4)]`, measured 7D joint positions, raw uint8 RGB and a companion `metainfo.json`. HDF5, metadata, split lock, evaluator, generator and simulator provenance are hashed. The generator does not manufacture zero joint state or silently substitute an instruction.

**Image convention:** new replay HDF5 frames are raw simulator/OpenGL RGB (`raw_opengl`) and need no vertical flip. The released author-refined HDF5 has the author's vertical flip and is tagged `libero_mem_refined`; the preparation path undoes that transform once. Source convention is locked and passed to both the offline memory writer and training sharder. Both paths deliver canonical raw RGB to the unchanged policy processor. Never infer the convention from the `mem` domain name.

To generate every split, use one fresh output directory and the same parent lock/runtime/config. Each command is resumable only under its recorded source, code and arguments:

```powershell
foreach ($split in @("train", "val", "test")) {
  .\scripts\run_generate_derived_demonstrations.ps1 -Tasks T1, T3 -Split $split -RequireSuccess
}

python scripts/lock_libero_mem_derived_split.py `
  --parent-lock experiments/training/results_mem_2/mem-adapter-v1/dataset-split.lock.json `
  --derived-dir data/libero_mem_derived_v1 `
  --output experiments/training/results_mem_2/libero-mem-derived-v1/split.lock.json
```

The derived lock is written only after all six task/split replays finish using the complete parent roster. Then generate RGB memory with `scripts/prepare_libero_mem_sft.py --source-kind derived_raw --data-dir data/libero_mem_derived_v1 --split-lock <derived-lock>`, once per task, and prepare matched mixed shards with `scripts/prepare_mixed_memory_sft.py --mem-root data/libero_mem_derived_v1 --split-lock <derived-lock> --memory-index <T1-index> <T3-index>`. Use the same lock and shards for the no-memory and memory training conditions.

## Current evaluation evidence

The evaluator only exposes SmolVLA B0 (original checkpoint) and F1 (the current LoRA adapter with RGB causal memory). MiniVLA/OpenVLA are not wired into this runner yet. The existing 20-episode-per-condition run is in `experiments/evaluation/results_mem_2/step5_test_20261109-093744/`; it predates derived-data training and must not be labelled as a result from the derived demonstrations.

| Condition | Episodes | Full successes | Mean SCR |
|---|---:|---:|---:|
| B0 | 20 | 0 | 0.050 |
| F1 | 20 | 1 | 0.133 |

Both conditions used policy seed 42 and the same ten state hashes for each task. T1 had 0/10 successes and SCR 0.1 in both. T3 had 0/10 B0 successes and 1/10 F1 successes. This single-seed result does not establish a robust gain or isolate memory, since F1 also changes the trained checkpoint and perception path. A matched F0 checkpoint and repeated paired runs are required for those claims.

Paper Table 4 reported LIBERO-Mem mean subgoal completion of 5.0% for π0, 0% for SlotVLA h=1, 5.0% for SlotVLA h=8, and 14.8% for Naive Embodied-SlotSSM. Those values cover the paper's ten tasks, original runtime and model setup; they are context only and are not numerically comparable with this T1/T3 suite.
